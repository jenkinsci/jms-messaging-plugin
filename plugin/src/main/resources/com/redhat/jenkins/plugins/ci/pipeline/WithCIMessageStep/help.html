Subscribe to an ActiveMQ, RabbitMQ, or Kafka response destination before running the enclosed Pipeline body.

The body starts only after the consumer is ready. It can send a request and run other steps while responses are buffered. After the body completes, this step waits for a matching message and returns its JSON content.

The message timeout is in minutes and starts after the body finishes. Use a Pipeline timeout around the whole block to bound setup and body execution as well.

RabbitMQ: leave both the provider queue and the queue override empty to create a temporary exclusive queue. Generated queues are cleaned up; configured queues are preserved.

ActiveMQ: queue consumers or non-durable topic subscriptions are established before the body.

Kafka: partition assignment and initial offsets are resolved before the body. Polling continues during the body; the matching response offset is committed after successful completion.

An active subscription cannot resume after a Jenkins restart, so the step fails explicitly without replaying its body.
